# Memeizer backend

Бэкенд здесь — локальные репозитории, OCR, база данных и фоновые задачи Android-приложения. Используй существующий `tools/backend`, не создавай дополнительный сервер или копию CLI.

## Подготовка

- Запускай команды из корня репозитория, где находятся `tools/backend` и `gradlew`. Все пути ниже указаны относительно корня.
- Нужны Python 3, `adb` в PATH и актуальная debug-сборка на устройстве. Release-сборка не содержит точку доступа harness.
- Выбирай устройство через `tools/backend --serial SERIAL ...` или `ANDROID_SERIAL`. Опция `--serial` стоит перед подкомандой. При нескольких устройствах используй цель из контекста; если она неизвестна, уточни выбор.
- Начинай с `status`. Если точка доступа не найдена, проверь устройство и сборку. Когда установка входит в текущую задачу, собери и установи debug APK по инструкциям репозитория. Не очищай данные приложения для исправления подключения.

## Команды

```bash
tools/backend status
tools/backend search "кот"
tools/backend search "hello"
tools/backend search ""
tools/backend image 42
tools/backend index --wait
tools/backend index --force --wait --timeout 600
tools/backend --serial emulator-5554 status
```

ID `42` — пример: возьми реальный `image_id` из поиска или запроса пользователя.

| Команда | Результат |
| --- | --- |
| `status` | Папки, включая отключённые, сохранённые разрешения чтения, количества изображений по `active` и `index_status`, ручные и периодические задачи |
| `search QUERY` | Реальный `SearchRepository` с нормализацией запроса; максимум 100 результатов |
| `search ""` | Активная галерея; максимум 100 изображений |
| `image ID` | Строка изображения, OCR с ошибками и записи FTS, включая неактивный кэш |
| `index` | Новая инкрементальная задача по выбранным папкам; возвращает `work_id` |
| `index --wait` | Ожидание именно созданной задачи, включая очередь; по умолчанию 300 секунд |
| `index --force --wait` | Повторный OCR в том числе неизменившихся изображений |

`status`, `search` и `image` предназначены для диагностики. `index` меняет индекс: запускай его, когда переиндексация или проверка с её выполнением входит в запрос пользователя. Для простого осмотра состояния он не нужен. Используй `--force`, когда требуется повторная проверка OCR, а не как стандартный первый шаг.

## Интерпретация и проверка результата

- JSON поступает в stdout; сообщения ожидания — в stderr. Успешный ответ содержит `ok: true` и `data`, ошибка — `ok: false`. Причина ошибки находится в `error` или, для завершившейся задачи, в `data.error`.
- Коды завершения: `0` — успех, `1` — ошибка команды или задачи, `2` — неверные аргументы, `124` — таймаут ожидания, `130` — прерывание.
- Таймаут и прерывание **не отменяют индексацию**. Сохрани `work_id` и найди его в `status` → `manual_work`. Если связь оборвалась при отправке `index`, задача могла уже попасть в очередь: проверь `status` перед повторной отправкой. Повторный `index` создаёт новую задачу, а не возобновляет ожидание старой.
- Harness добавляет ручную задачу без отмены существующих. Другие действия приложения могут отменить её; `CANCELLED` — не успешная проверка.
- `SUCCEEDED` означает завершение задачи, но отдельные картинки могут иметь `FAILED`. После индексации проверь количества в `status`, ожидаемые поисковые совпадения и при необходимости `image ID`.
- Сохранённое разрешение чтения не доказывает доступность папки. Пустая галерея позволяет проверить транспорт и завершение пустой задачи, но не качество OCR или поиск по реальным данным.
- OCR или FTS у неактивной картинки сами по себе не ошибка: приложение сохраняет кэш. Текстовый поиск показывает только активные изображения со статусом `INDEXED`; пустой запрос показывает активную галерею.
- Для проверки поиска используй известные русские и английские надписи и пустой запрос. Для OCR сопоставь ожидаемый текст конкретной картинки с `image ID`, затем с поиском. Сообщи, какие данные и сценарии реально проверены.

## Изменения самого harness

Консольные регрессионные тесты:

```bash
python3 -B -m unittest discover -s tools -p 'test_*.py'
```

При изменении Android-части собери debug APK и проверь затронутые команды на целевом устройстве. При изменении регистрации debug-компонентов проверь их отсутствие в release manifest. Дополнительные тесты выбирай по затронутому поведению; полный набор instrumentation-тестов не нужен для простого чтения состояния.

Реализация: `tools/backend` и `app/src/debug/java/com/darkesttrololo/memeizer/DebugBackendProvider.kt`. Установка и описание: раздел `Backend Harness (Debug Only)` в `README.md`. При расхождении skill с кодом проверь актуальный `tools/backend --help` и реализацию.
